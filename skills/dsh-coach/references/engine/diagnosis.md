# Diagnosis：针对性诊断

来源：原文 §四；改动经审核裁定 W01（压缩题量但保留覆盖）、W03、W11（等价替代仅保留字段）。

## 原则

- 诊断围绕**用户的目标**设计，不使用与项目无关的通用考试。
- 诊断的作用是建立证据起点，不是筛选或淘汰。目的是让"待验证"尽快变成"已验证/部分验证"。
- **自述分三类**（见 `intake.md` 与 R3）：**能力自述**只作线索，诊断结论必须来自用户的实际作答或成果；**缺口自述**（"我没学过 X"）**直接采信**，不走诊断，直接转 R9 讲授；**操作自述**（"我跑了一次，输出是 X"）无反证时按"部分验证"接受，**不得要求重复实测，也不得要求补交实测材料**。

## 三类最小覆盖（不可省略）

1. 一项**理解或结果预测**；
2. 一项**问题定位**；
3. 一项**小型实现或方案设计**。

压缩交互成本的方式是**减少题量、合并呈现**（一次 1–3 题），不是跳过覆盖。缺少任一类时，能力画像中对应维度不得标"已验证"。

## 题型库

从领域包 `references/domains/<domain>/` 的 `diagnosis` 小节取题。选题目时优先选择**贴近用户当前项目**的题目；领域包题目均标注所考察维度与最小诊断类别。

**取题前置检查（必做）**：每道题的题面标有 `类型`（事实性／推理性／综合）与 `前置知识`。取题时必须核对：

- **事实性题不得作为首次接触题**——学员尚未学过该知识点时，先按 R9 讲授，再用该题作**确认题**；
- `前置知识` 未满足的题**不得使用**：先补前置，或换一道不需要该前置的题；
- **`前置知识` 是自由文本，状态层没有知识点级记录**，因此**无法判定时按"未满足"处理**（先按 R9 讲授，或换题），不得默认视为满足；
- 技能类任务同样适用：讲授只改变"回补的形式"，不改变"先尝试"的顺序。

**大文件不要整篇读入**：领域包题库可能很大（数百行）。先读它的索引/题号清单（通常在文件头部或末尾的"最小覆盖索引"），确定本次要用的题号，再按题号定位并只读该题正文。一次诊断只读 2–4 道题。

若某领域难以构造"小型实现"（例如纯设计类项目），改用**方案评审**替代，并在 `state.capability[].evidence` 中注明替代形式；等价替代是领域包字段，引擎不额外放宽。

## 动态难度

| 观察 | 调整 |
|---|---|
| 回答顺利 | 提高开放性、边界与变化要求 |
| 回答困难 | 缩小问题，检查前置知识；**若该前置属于学员未学过的知识类内容 → 直接讲授（R9）** |
| 答案正确但理由不清 | 继续追问机制 |
| 会解释但不会实现 | 增加实践任务 |
| 能实现但不会排错 | 增加故障诊断与验证任务 |
| **概念未理解且学员未学过** | **直接讲授（R9）**：概念 → 为什么当前任务需要 → 最小示例 → 用户亲自应用 → 确认题 |

## 结论标记

每项能力结论必须标为：

- **已验证**：有用户回答、成果、运行结果或测试支持，**且满足下表对应类型的强度条件**；
- **部分验证**：已有证据，但覆盖不足（**知识类单题正确一律停留在此档**）；
- **待验证**：目前仅为自述或推测。

**证据按结论类型分层**（既防"问一次就发已验证"，也防"读代码能判的却要求实测"）：

| 结论类型 | 判为"已验证"的条件 | `artifact` |
|---|---|---|
| **知识类**（事实、机制、术语、顺序、规则） | **无提示下解释机制** ＋ **迁移到新情境**（复用 `adapt.md` 的迁移检查与 `review-acceptance.md` 的检索式复述）。**单题正确只算"部分验证"** | 问答记录（题目编号＋学员原话摘录） |
| **行为类**（代码、功能、排错、设计取舍） | 运行结果、测试或断言支持 | 文件与行号、日志片段、截图位置、可复现步骤 |

写入 `state.capability[]` 时：`status=已验证` 必须带 `evidence` 引用（指向 `state.evidence[].id`），且等级 ≥3；无证据时等级 ≤2 且 `status=待验证`。校验器会强制这三条；知识类结论的强度另有一条 warn 提醒（见 `state.md`）。

## 收尾

- 给出简版能力画像（维度 / 等级 / 状态 / 证据 / 主要缺口 / 对当前目标的影响）。
- 明确写出"下一轮待验证的假设"——例如"假设能在**无提示**下独立完成本阶段的核心机制，并在边界条件下正确处理，将在阶段 1 任务 2 验证"。
- 请用户确认或修正；用户否定的结论降级为"待验证"，不要争论。
