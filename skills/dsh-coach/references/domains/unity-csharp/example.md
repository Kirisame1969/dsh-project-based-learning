**作答记录（示意）**

- **Q1-1**：顺序答对（`Awake → OnEnable → Start → Update`），也答对了「`Start` 只一次、`OnEnable` 可多次」。
  但答错一处：认为「对象没启用时 `Awake` 也不会执行」；并认为 `SetActive(true)` 会重新触发 `Start`。
  → 核心顺序正确、机制有一处明确错误。
- **Q4-2**：只给出 2 条原因（「两边都要勾 `Is Trigger`」——此条本身错误；「代码拼写」——已排除）。
  未提及 **Layer 碰撞矩阵**、**刚体类型组合**、**碰撞体尺寸为 0**。也没有提出用 Gizmos 先确认几何重叠。
  → 这是 2D 原型最高频卡点，而排查手段明显不足。
- **Q6-1**：20 分钟内写出 `Queue<GameObject>` 结构，`Get`/`Release` 正确，主动说明「用 `SetActive` 而不是 `Destroy`」。
  但**遗漏状态重置**（没意识到复用对象会带回上次的脏状态），也答不出场景切换后池内引用会变成已销毁对象。
  → 主体成立，边界缺失。

## 四、任务审阅报告

**审阅对象**：阶段 1 任务 2「跳跃与着地检测」提交的 `PlayerJump.cs`
**材料来源**：学员在对话中粘贴的完整文件内容（教练据此核对，标注为「已核对」）

### 阻塞

**B-1｜跳跃位移写在 `Update` 里直接改 `transform.position`**

| 要素 | 内容 |
| --- | --- |
| 位置 | `PlayerJump.cs` 第 24–31 行（`Update` 方法体内） |
| 发生机制 | `Update` 按渲染帧执行，物理按固定步长推进，两者调用次数比例不固定；且直接给 `transform.position` 赋值绕过了物理引擎的解算与插值。 |
| 实际影响 | 跳跃高度随帧率变化——在学员的无独显笔记本上会明显偏低。**直接导致验收标准第 1、2 条无法成立。** |
| 最小修复方向 | 在 `Update` 里只记录「本帧是否按下跳跃」到 `bool` 字段，把位移与速度赋值移到 `FixedUpdate`，改用 `Rigidbody2D.linearVelocity` 处理。 |
| 修复后验证方式 | 把 `Application.targetFrameRate` 分别设为 15 与 60，各跳一次并打印最高点 y 值；两次差值应在肉眼/数值上一致。 |
| 依据 | 学员提交的 `PlayerJump.cs` 第 24–31 行（粘贴于对话，教练已逐行阅读） |
| 核对状态 | 已核对 |

**B-2｜着地检测用绝对高度 `transform.position.y <= 0` 判断**

| 要素 | 内容 |
| --- | --- |
| 位置 | `PlayerJump.cs` 第 38 行 |
| 发生机制 | 用「角色世界坐标高度」代替「与地面几何接触」的判断。这只在「地面恰好位于 y=0」时成立，本质是把关卡布局硬编码进了逻辑。 |
| 实际影响 | 只要场景里存在高台，角色站上去后 `isGrounded` 永远为 `false`，在高台上按空格无法起跳。**与验收标准第 2 条冲突**，且后续加平台时必须改代码。 |
| 最小修复方向 | 改用几何检测：从角色底部向下做 `Physics2D.Raycast`，或用 `Physics2D.OverlapCircle` 检测脚底小圆是否与地面 Layer 相交；把地面 Layer 做成可配置字段。 |
| 修复后验证方式 | 在场景里加一个 y = 3 的高台，角色站上去后跳跃应可用；再加一个 y = −2 的凹地重复一次。 |
| 依据 | `PlayerJump.cs` 第 38 行 |
| 核对状态 | 已核对 |

### 重要

**I-1｜起跳后未立即清掉着地标记，可以空中二段跳**

| 要素 | 内容 |
| --- | --- |
| 位置 | `PlayerJump.cs` 第 40–46 行 |
| 发生机制 | `isGrounded` 每帧重新计算，但起跳当帧到角色真正离开碰撞体之间还有若干帧仍为 `true`；这期间再次按空格就会被判定为合法起跳。 |
| 实际影响 | 产生非预期二段跳，验收标准第 2 条「空中连按不产生第二次跳跃」不成立。 |
| 最小修复方向 | 在成功起跳的那一帧立即把 `isGrounded` 置为 `false`，由后续的几何检测重新置位。 |
| 修复后验证方式 | 落地后以最快手速连按空格 5 次，统计角色实际起跳次数；应为 1。 |
| 依据 | `PlayerJump.cs` 第 40–46 行 |
| 核对状态 | 已核对 |

**I-2｜金币判定用了 `OnTriggerStay2D` 但没有去重**

| 要素 | 内容 |
| --- | --- |
| 位置 | `Coin.cs` 第 12–16 行（`OnTriggerStay2D`） |
| 发生机制 | 停留在触发器内的每一帧都会调用 `OnTriggerStay2D`；文件里既没有 `bool` 标记也没有销毁金币，所以加分会被反复执行。 |
| 实际影响 | 站在金币上一秒会加几十分，分数完全失去意义。对应验收标准第 3 条「只打印一次」。 |
| 最小修复方向 | 改用 `OnTriggerEnter2D`（重叠开始时只触发一次），并在其中调用 `Destroy(gameObject)` 或置 `bool collected` 做幂等保护。 |
| 修复后验证方式 | 站在金币位置不动 2 秒，Console 应只出现 1 条日志，分数只 +1。 |
| 依据 | 学员提交的 `Coin.cs` 第 12–16 行 |
| 核对状态 | 已核对 |

### 建议

**S-1｜`jumpForce` 是硬编码的魔法数字**

| 要素 | 内容 |
| --- | --- |
| 位置 | `PlayerJump.cs` 第 9 行：`private float jumpForce = 9f;` |
| 发生机制 | 数值写死在代码里，调手感必须改代码并等待重新编译。 |
| 实际影响 | 不阻塞功能，但会让后续每一次手感微调都变慢。 |
| 最小修复方向 | 改为 `[SerializeField] private float jumpForce = 9f;`，在 Inspector 里调。 |
| 修复后验证方式 | 在 Inspector 中把该值由 9 改为 14，跳跃应明显变高，且无需改代码。 |
| 依据 | `PlayerJump.cs` 第 9 行 |
| 核对状态 | 已核对 |

**S-2｜`Update` 里每帧拼接字符串打日志**

| 要素 | 内容 |
| --- | --- |
| 位置 | `PlayerJump.cs` 第 27 行：`Debug.Log("grounded=" + isGrounded);` |
| 发生机制 | 字符串拼接在 `Debug.Log` 调用**之前**就完成，每帧产生一个新的 `string`；且该日志在正式包里同样执行。 |
| 实际影响 | 目前场景简单，看不出问题；但这是后续性能优化时会被反复指出的每帧分配来源（见 `pitfalls.md` P-08）。 |
| 最小修复方向 | 调试完成后删除，或用条件编译/开关包起来。 |
| 修复后验证方式 | 打开 Profiler 的 GC Alloc 列，对比删除前后该帧的分配字节数。 |
| 依据 | `PlayerJump.cs` 第 27 行 |
| 核对状态 | 已核对 |
