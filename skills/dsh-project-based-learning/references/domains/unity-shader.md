# Unity Shader 粗略导航

## 覆盖范围

适用于在 Unity 中学习 Shader、材质、Sprite 视觉处理和屏幕滤镜。典型作品包括颜色处理、像素化、溶解与腐蚀、卷帘消散、CRT 效果、粒子拖尾和风格化火焰。

开始前确认实际渲染管线、Unity 版本、目标平台，以及效果作用于 Sprite、粒子、UI、普通网格还是全屏画面。不同管线的 Shader 结构和内置变量可能不同，不要凭另一管线的示例直接假设可用。

## 粗略路线

以下是依赖图，不是固定课程表：

1. **数据怎样到达屏幕**：Shader、Material、Renderer 的关系；顶点阶段、片元阶段；对象空间到裁剪空间；插值数据。
2. **纹理与颜色**：UV、纹理采样、RGBA、SpriteRenderer Color、Tint、透明度，以及颜色相乘的视觉意义。
3. **坐标塑形**：平移、缩放、重复、翻转、中心化、纵横比修正和 UV 量化；这是像素化与规则图案的基础。
4. **遮罩与可见性**：阈值、范围函数、平滑边缘、Alpha、裁剪与混合；这是溶解、腐蚀和形状消失的基础。
5. **时间与运动**：随时间滚动 UV、周期变化、方向控制和速度参数；用于扫描线、流动、拖尾表面运动和火焰上升感。
6. **非规则图案**：噪声、纹理遮罩、程序化扰动和抖动；先理解用途与输入输出，再决定使用贴图还是数学生成。
7. **效果组合**：按视觉层次组合遮罩、颜色、形变、发光感和动画。例如 CRT 可组合扫描线、轻微扭曲、色偏与噪点；腐蚀可组合噪声阈值、边缘带和透明裁剪。
8. **Unity 集成与性能**：属性暴露、每材质与每渲染器数据、批处理、过度绘制、纹理设置、Sprite Atlas，以及目标平台限制。

根据作品选择最短路径。例如单纯像素化通常不需要先学噪声；卷帘式消散可从 UV、阈值和时间直接切入；火焰效果需要的遮罩、时间与扰动可以边做边补。

## 关键门槛概念

- **片元、屏幕像素和纹素不是同一个概念**：片元着色器处理栅格化产生的候选片元；纹理采样读取纹素；最终屏幕像素还可能受分辨率、缩放、过滤与混合影响。
- **UV 是坐标，不是自动遍历图片的循环变量**：每个片元携带插值后的 UV，采样函数用它查询纹理。
- **Shader 与 Material 分工不同**：Shader 定义计算方式，Material 保存一组属性值；Renderer 还可能提供每个对象的数据。
- **透明需要整条渲染状态配合**：输出 Alpha 不一定自动产生正确透明效果，还要考虑队列、Blend、深度写入、裁剪和所用管线。
- **坐标比例影响形状**：直接在拉伸后的 UV 上画方格、圆或像素块，视觉上可能变成长方形；需要明确是在纹理空间、对象空间还是屏幕空间保持比例。

## 常见误区与风险

- 把 GPU 并行处理片元简化成“逐个遍历原图所有像素”，从而误解缩放、遮挡与重复采样；
- 忽略纹理 Filter Mode、压缩和 Pixels Per Unit 对像素风格的影响；
- 用 `Opaque` 标签或输出 Alpha 推断实际混合状态；
- 混淆左上/左下 UV 原点；不同资源导入、平台或屏幕采样路径需要依据实际管线核对；
- 只在一张正方形测试图上验证，未发现纵横比拉伸；
- 一次叠加大量噪声、颜色和动画代码，导致无法判断每一步作用；
- 在大量透明 Sprite 或粒子上制造高过度绘制，PC 上正常但目标设备性能不足。

## 教学取向

- 使用视觉结果明显、参数少的小变化；
- 第一次给 Shader 结构时说明每个区块的角色，但不逐符号讲完整文件；
- 新内置函数首次出现时解释输入、输出、值域和本次视觉作用；
- 数学先连接视觉含义，例如 `step` 是硬阈值、`smoothstep` 是带过渡区间的阈值；
- 每加入一个效果层先单独观察，再组合；
- 优先让学习者修改一个参数或表达式并预测局部变化。

## 版本核对

版本敏感信息优先从当前项目的 Shader、包清单、渲染管线设置和 Unity 官方文档核对。查资料时优先选择与项目 Unity 版本和管线相匹配的 ShaderLab、HLSL、URP 2D Renderer、Sprite Renderer、Shader Graph 或后处理官方文档。
