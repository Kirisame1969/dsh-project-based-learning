# Unity C# 粗略导航

## 覆盖范围

适用于用 C# 制作 Unity 游戏逻辑、理解组件模型、组织场景对象、调试运行时行为，并逐步改善项目结构。典型作品包括角色控制、交互、战斗、背包、UI、存档、关卡流程和小型完整游戏。

开始前确认 Unity 版本、输入系统、渲染或物理维度、目标平台和已有项目约定。不要因为某种架构常见，就在小项目中过早引入复杂框架。

## 粗略路线

以下是可按项目裁剪的依赖图：

1. **Unity 对象与组件**：GameObject、Component、Transform、Inspector 引用和序列化字段。
2. **生命周期与时间**：初始化、逐帧更新、固定物理更新、启用/禁用和销毁；理解执行时机后再组织行为。
3. **输入、运动与物理**：输入采集、速度与位移、碰撞体、触发器和刚体；区分直接变换与物理系统。
4. **Prefab 与可配置数据**：把重复对象和参数从硬编码中分离，理解实例、引用和资源关系。
5. **对象通信与状态**：直接引用、事件、接口和状态机；从当前耦合问题出发选择，不先背架构名称。
6. **UI 与游戏流程**：让显示响应数据变化，组织暂停、失败、重生、场景切换等状态。
7. **数据持久化与内容扩展**：配置数据、存档、关卡或物品内容；区分运行时状态与资产数据。
8. **质量与性能**：调试、测试边界、对象生命周期、分配、池化和性能分析；只在真实瓶颈或规模需要时优化。

## 关键门槛概念

- C# 对象、Unity 组件和场景中的对象实例不是同一层概念；
- 生命周期函数由 Unity 调用，普通方法由代码显式调用；
- 帧更新和物理更新具有不同时间语义；
- Inspector 中的序列化引用与运行时查找有不同生命周期和失败方式；
- 事件能降低发送者对接收者的直接依赖，但订阅与取消订阅必须匹配；
- Prefab、场景实例和 ScriptableObject 资产的数据归属不同。

## 常见误区与风险

- 用背诵生命周期顺序代替观察当前对象的实际状态；
- 在 `Update` 中重复执行昂贵查找或无条件创建对象；
- 混用 Transform 位移与 Rigidbody 物理行为导致抖动或穿透；
- 未检查空引用、对象销毁和场景切换后的引用有效性；
- 事件重复订阅或未取消，引发重复响应和隐蔽生命周期问题；
- 为展示“架构”过早增加管理器、单例和抽象层；
- 把编辑器设置或资源引用错误误判成 C# 逻辑能力不足。

## 教学取向

- 从可运行的组件与场景行为开始，将 C# 语法放入实际数据流中解释；
- 新语法首次出现时简短说明，例如属性、泛型、委托、Lambda 或字符串插值；
- 调试时要求观察具体值、调用时机和对象身份，而不是随机改代码；
- 先让单一职责的小组件工作，再讨论复用和解耦；
- 完整示例之后通过修改条件、替换输入或增加一个相邻行为确认理解。

## 版本核对

涉及输入系统、序列化、包 API、编辑器工作流或平台限制时，优先检查当前项目的 `ProjectVersion.txt`、包清单、项目设置和对应 Unity 官方文档。不要混用不同 Unity 大版本或旧输入系统与新输入系统的写法而不说明前提。
