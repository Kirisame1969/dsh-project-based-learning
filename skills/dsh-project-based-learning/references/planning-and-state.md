# 路线与学习状态

## 1. 何时维护状态

仅为跨多轮的持续课程维护 `.learning/state.json`。快速问答、一次解释和单次带练不创建状态。

状态服务于三件事：

1. 记住长期教学偏好和项目边界；
2. 记住当前结果、下一步与粗略方向；
3. 区分“讲过”与“已经通过实践展示”。

状态不是聊天流水账、成绩单或完整课程内容仓库。

## 2. 路线粒度

路线只保留三个时间尺度：

- `now`：正在完成的一到三个可见结果；
- `next`：紧接着可能需要的方向；
- `later`：与最终作品相关、目前不应展开的主题。

根据项目变化随时重排。不要把领域导航逐项复制成课程表，也不要预先生成几十节课。

## 3. 概念状态

每个概念选择一个状态：

- `尚未接触`：路线中可能需要，但尚未教学；
- `已讲授待实践`：已经解释或示范，尚无真实使用证据；
- `带练中`：学习者在提示、示范或共同排错下使用过；
- `可在熟悉任务中独立使用`：在相似情境中能独立完成、修改或解释；
- `已迁移到新任务`：在不同情境中主动选择并正确使用。

不得依据能力自述直接提升后两种状态。也不得因为 AI 给过完整代码，就把对应概念记为已掌握。

## 4. 可接受的证据

证据可以是简短文字，不强制附件或统一格式，例如：

- 用户修改参数并准确描述视觉变化；
- 用户独立增加一个相邻功能；
- 用户根据报错定位到正确机制并完成修复；
- 用户解释自己的方案选择；
- 用户将同一机制用于新的作品部分。

环境故障、工具安装失败和资源导入问题不作为能力不足的证据。

## 5. 更新条件

仅在下列情况更新状态：

- 教学偏好或项目边界改变；
- 出现新的可观察实践证据；
- 完成一个真实里程碑；
- `now / next / later` 发生变化；
- 新证据要求明显增加或减少支架。

更新时：

1. 先读取现有文件并保留未知字段；
2. 只修改受本轮影响的字段；
3. `revision` 加一并刷新 `updatedAt`；
4. 运行校验器；
5. 只向用户说明有意义的记录变化，不汇报内部机械步骤。

## 6. 最小结构

以 `assets/state.template.json` 为准。数组内容保持短小：

- `preferences`：长期有效的教学偏好；
- `context`：领域、项目、环境与排除项；
- `goal`：作品结果、成功信号和非目标；
- `current`：当前里程碑、本次结果、新知识和下一动作；
- `route`：现在、接下来、以后；
- `concepts`：概念状态、证据与下一步支架；
- `artifacts`：真正影响课程判断的作品或文件；
- `decisions`：重要路线决定及理由。

## 7. 旧状态迁移

迁移 `.coach/state.json` 时：

- 保留目标、完成判据、环境、非目标、当前任务和路线文字；
- 将旧路线压缩到 `now / next / later`；
- 不迁移数字能力等级；
- 不把旧“已验证”自动映射为任何具体概念；
- 在 `decisions` 中记录迁移来源，提醒下一轮人工核对。

迁移是一次性操作。新课程只维护 `.learning/state.json`，不保持两套状态同步。
