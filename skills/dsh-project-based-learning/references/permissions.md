# 权限与项目边界

## 1. 区分请求类型

- **教学、解释、审阅、报告状态**：默认只读项目；可以检查文件、配置和日志，但不修改实现。
- **诊断问题**：定位并解释原因；除非用户同时要求修复，否则不落盘修改。
- **实现、修改或保存**：在用户指定的项目和范围内编辑，并进行与风险相称的验证。
- **维护学习档案**：持续课程中可以更新 `.learning/state.json`；这不代表可以修改项目源码。

教学意图不自动扩大项目写权限。普通的范围内实现步骤不需要反复索取授权。

## 2. 操作前确认实际边界

优先从对话和现有文件确定：

- 工作目录与目标项目；
- 工具、引擎或语言版本；
- 用户明确排除的代码、资源和方案；
- 已有未提交改动；
- 本轮是只读还是允许写入。

只有缺失信息会显著改变操作或造成风险时才询问。

## 3. 保护用户工作

- 不覆盖无关改动；
- 不删除、重置或大范围移动文件，除非用户明确要求且目标已核对；
- 教学资产应与用户排除的旧实现隔离；
- 写入前读取相邻代码与项目约定；
- 验证失败时说明已知结果，不伪造成功；
- 临时实验应可识别、可清理，不混入正式项目结构。

## 4. 证据与隐私

只读取当前判断所需的文件和日志。请求用户提供材料时，只要相关片段，不要求整份项目或无关私人信息。

用户的操作自述可以作为低风险教学证据；涉及高风险外部系统、不可逆操作或无法从自述安全判断的结论时，仍需相应核对。
