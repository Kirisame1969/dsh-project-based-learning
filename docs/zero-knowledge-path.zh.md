# 零基础路径回归清单

> **用途**：本次教学缺陷修复（引擎 1.1.0 / R9·R10）的验收与回归清单。
> 每条给出「触发 → 必须出现 → 禁止出现 → 机械化程度」，可在真实会话中逐条核对。
> **来源**：使用者反馈的三条缺陷（只问不教／过度要求实测／该教的让人自己悟）＋ 第 1 轮三份独立审核的最小加固要求。

## 为什么需要它

上一版引擎的失败不是"规则实现错了"，而是**散文规则在真实对话里被误用**：条款自洽、机械校验全绿、CI 全绿，但学习者体验是坏的。因此修复必须配一份**面向行为的清单**，并且明确哪些项**机械能拦**、哪些项**只能人工核对**。

## 清单

| # | 触发场景 | 必须出现 | 禁止出现 | 机械化程度 |
|---|---|---|---|---|
| **Z1** | 学员说「我没学过 X／我不了解 Y」（缺口自述） | 直接进入 **R9 讲授**：概念 → 为什么当前任务需要 → 最小示例 → 用户亲自应用 → 确认题 | 先出诊断题；把缺口自述记成"待验证"后继续考 | 部分：状态中应出现该知识点的问答记录（`stage: 0`） |
| **Z2** | 内容是**事实性知识**且满足 R9 条件③ 的 (a)(b)(c)（API 名称与签名、调用与执行顺序、语言与类型规则、文档已明的默认值） | 讲授 + 确认题 | 要求**实测**——**R10 例外成立时除外**：文档未覆盖／自相矛盾／版本差异时仍须实测，且必须先给出所依据的文档章节或行号 | 间接：由 Z6/Z7 的证据类型规则约束 |
| **Z3** | 任何一次要求实测之前 | 说明"为什么这一点无法从代码或文档判定"，并**给出所依据的文档章节或文件行号** | 无理由的实测要求；只说"你跑一下看看" | 部分：知识类结论出现实测要求即可判违规 |
| **Z4** | 学员说「我跑了一次，输出是 X」／「我按你说的改了」（操作自述） | 按**部分验证**接受，继续推进 | 就同一件事**再次**要求实测；要求补交截图等实测材料 | 部分：同一结论下不应出现重复的实测要求 |
| **Z5** | 技能类任务（写代码、排错、设计、拆解） | 仍按 R1／R2 **先让学员动手**；R9 只改变"回补的形式" | 因 R9 把技能任务改成"我讲完你照着敲"；让学员跳过亲手实现 | 机械：`route[].userOnly` 非空且验收时逐项核对 |
| **Z6** | 知识类结论要标"已验证" | **无提示下解释机制 ＋ 迁移到新情境**（检索式复述／迁移检查） | **单题正确即标"已验证"** | 部分：校验器 `ST-W7` warn（**只提醒、不拦截**）；强制力靠本清单 |
| **Z7** | 行为类结论要标"已验证" | 运行结果、测试或可核对材料（文件与行号／日志／截图／复现步骤） | 用**问答记录**充当行为类结论的证据 | 部分：`artifact` 不得是占位符；类型匹配靠人工 |
| **Z8** | 一次讲授 | **一个机制 ＋ 一个最小示例**；讲完必须回到一次学员产出 | 整章式讲课；讲完不出确认题；"讲 2 点→确认题→再讲 2 点"式循环 | 人工核对 |
| **Z9** | 确认题答错 | **回退到更小机制**并换一种表征重讲 | 把同一段解释再说一遍；直接给答案了事 | 人工核对 |
| **Z10** | 三条 R9 触发都不成立时 | 一律走 **R1／R2**（先做后教、分级提示） | 把 R9 当加速项，逢题就讲 | 人工核对 |

## 在真实会话里怎么用

1. **Z1／Z2 判据**：对教练说
   > 我完全没学过 Unity 的生命周期，请评估我的水平。

   若它先出题（例如"预测下面脚本的 Console 输出顺序"）而不是先讲，**Z1 失败**。反过来，若它讲完却不给确认题，**Z8 失败**。

2. **Z3 判据**：任何一次被要求实测时，检查是否给出了"为什么无法从代码或文档判定"以及文档章节／行号。没有 → 违规。

3. **Z4 判据**：说
   > 我按你说的跑过了，输出是 A B C D。

   若它仍要求你再跑一次、或要你补截图 → 违规。

4. **Z5 判据**：进入实现类任务后，确认代码仍由学员本人写、本人运行（`route[].userOnly` 逐项核对）。

5. **Z6／Z7 判据**：跑校验器，看是否有 `ST-W7` 提醒：

   ```bash
   node skills/dsh-project-based-learning/scripts/coach-validate.mjs --state .coach/state.json
   ```

   > `ST-W7` 是 **warn，不是门禁**（CI 退出码只看 error）。这是 2.1 修订的明确取舍：漏报的代价是"可能漂移"（有本清单兜底），误报的代价是每次正常教学都被阻塞。

6. **Z8／Z9／Z10 判据**：翻一遍对话记录，数一次讲授覆盖了几个机制、讲完学员做了什么、答错后是"换表征"还是"重复同段"。

## 机械化覆盖边界（如实声明）

- **机械能拦**：`userOnly` 非空、`artifact` 非占位符、`stage ≥ 0`、`ST-W7` 提醒（不拦截）；
- **只能人工核对**：Z1、Z2、Z3、Z8、Z9、Z10 属**对话质量**；Z6、Z7 的类型匹配也无法机械判定（`artifact` 是自由文本）；
- 因此：**"校验通过"不等于"教学合格"**——与 `state.md` 的既有声明一致。本清单**每阶段**跑一次，而不是每次落盘都跑。
