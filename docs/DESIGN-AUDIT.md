# 教学教练插件：弱点分析与改动审核（第 1–2 轮）

> **勘误（2026-09-12）**：本文记录的是 1.0.0 / 1.1.0 时期的实况。技能目录已于 **1.2.0** 由 `skills/dsh-coach/` 改名为 `skills/dsh-project-based-learning/`，技能注册名同步变更；下文旧路径请按此对应，其余内容未改写。

对象：`通用AI项目制教学工作流.md`（379 行，14 节，下称"原文"）
产物：可安装的 DSH 技能包 `coach/`（引擎 + Unity/C# 领域包 + 状态契约 + 校验器）
本文性质：**改动前置审核记录**。任何对原文的改动都必须先通过下方六项检验，且必须经过第二轮反方复审；未通过者驳回或延后，不以"改进"名义直接下手。

---

## 0. 审核协议

| 检验 | 内容 | 不通过的后果 |
|---|---|---|
| A 必要性 | 原文在该处是否真的失败？给出可复现的失败场景（必须引用行号） | 不成问题则为"过度设计"，直接驳回 |
| B 最小性 | 是否存在更小的改动达到同样效果？ | 取最小可行方案，大改延后 |
| C 反方论证 | 原文这样写保护了什么？改动会失去什么？（写出最强反方） | 反方更强则驳回改动 |
| D 回归 | 是否与其它条款冲突？是否引入新失败模式（含权限、安全、错误归因）？ | 有冲突则需附缓解条款，否则驳回 |
| E 可验证 | 改动后如何判定有效？（须是可观察信号，不能是"感觉更好"） | 不可验证则驳回 |
| F 复审 | 隔一轮重读原文与裁定，检查是否被第一轮结论锚定；给出维持/翻案 | 翻案必须记录 |

裁定枚举：**采纳 / 修改后采纳 / 驳回 / 延后**。

**原则**：原文的默认状态是"保留"。改动必须自证必要，而不是新设计自证优越。

## 1. 弱点清单与逐条裁定

### W01 前导漏斗过长

- **位置**：§二（30–47）、§三（51–65）、§四（69–101）、§五（105–133）、§六（143–163）叠加 §十二"每轮问题尽量不超过 3 个"（345）。
- **失败场景**：用户说"我想做一个 2D 平台跳跃原型"。教练按 §一→§六 顺序推进，每轮至多 3 问，用户需 6–10 轮才拿到第一张任务卡，期间零产出。
- **候选**：R1 把 §二/§三 合并为一次结构化 intake，诊断压缩为 3 题；R2 设"新手快通道"，直接跳过诊断。
- **A**：成立。信息量与轮次上限的乘积决定了漏斗长度，这是结构性摩擦，不是执行偏差。
- **B**：R1 更小；R2 改动更大。
- **C**：强反方——诊断是证据链的根基（§四 97–101 三态标记；§八 262"只有能解释、修改并验证后，才能作为个人能力证据"）。跳过诊断则基线全为"待验证"，起点只能取信自述，证据链从第一步断裂。**这是全文最不能动的机制。**
- **D**：R1 无冲突。R2 与 §四、§八 直接冲突。
- **E**：intake 到首张任务卡的消息轮数 ≤ 2，且仍覆盖"理解预测 + 问题定位 + 小型实现"三类。
- **F 复审**：维持。压缩**提问方式**，不压缩**证据覆盖**。
- **裁定**：**修改后采纳 R1；驳回 R2。**

### W02 提示词体积与注意力稀释

- **位置**：全文 379 行；分散规则如 §七.3（203–213）、§十二（347）。
- **失败场景**：长会话中模型漏掉"不要跳到第 5 级提示""不重复完整路线"，且没有任何机制能发现漏了。
- **候选**：R1 拆分加载（常驻引擎 + 按需 references）；R2 关键规则改为结构化校验。
- **A**：成立，但部分原因是常驻规则数量本身过大。
- **B**：R1 最小（不改内容，只改加载方式）。
- **C**：反方——拆分后模型可能"忘记读"参考文件。缓解：SKILL.md 必须给出**指令 → 必读文件**的强制映射表。
- **D**：无冲突。R2 依赖宿主插件（cordis），超出当前工作区可行范围。
- **E**：常驻体积从 379 行降到约 150 行；级别参数化后可由校验器检查。
- **F 复审**：维持。
- **裁定**：**采纳 R1；R2 延后至宿主插件阶段。**

### W03 能力画像的虚假精确

- **位置**：§五（117–141）；张力源自 §三 67"自述不能当作已验证的能力证明"与 §五 118 仍要求给 1–5 分。
- **失败场景**：无任何证据时给出"实际应用 3 分"，教练与用户都当真；7×6 表格跨轮重写的 token 成本高。
- **候选**：R1 无证据维度等级封顶且必须标"待验证"，证据列必填引用；R2 删除 1–5 等级。
- **A**：成立（张力客观存在）。
- **B**：R1 最小。R2 破坏沟通效率。
- **C**：反方——等级是教练与用户的共同语言，删除后无法表达差距与进步幅度。R1 保留等级。
- **D**：与 §四三态标记一致。
- **E**：可机械校验——`status=已验证 ⇒ evidence 非空且 level≥3`；无 evidence ⇒ `level≤2` 且 `status=待验证`。
- **F 复审**：维持。
- **裁定**：**修改后采纳 R1；驳回 R2。**

### W04 三份状态文档无单一事实源

- **位置**：§五基线（107–133）、§六路线（149–161）、§十档案（297–308）。
- **失败场景**：长会话中基线写"阶段 2"、档案写"阶段 3"；§十 318–323 只规定证据权重，未规定文档间合并规则。
- **候选**：R1 三合一为单一状态源 + 生成式人类视图；R2 保留三份并声明"以档案为准"。
- **A**：成立。
- **B**：R1 略大但消除根因；R2 只是把冲突规则化。
- **C**：反方——合并后单文件变大，模型每轮重写全文易截断。缓解：状态源用 JSON（机器校验、字段级更新），人类视图为**生成物**。
- **D**：与 §十 308"只保存结论和证据摘要"一致。
- **E**：校验器强制 `current.stage` 必须存在于 `route`；`PROGRESS.md` 标注"生成物，勿手工编辑"。
- **F 复审**：维持。
- **裁定**：**采纳 R1。**

### W05 持久化不可靠与降级方案摩擦

- **位置**：§十（297–325）。
- **失败场景**：AI 声称"已保存学习档案"但未写盘；新会话全部丢失。原降级方案要求用户手工复制粘贴（325）。
- **候选**：R1 写入工作区真实文件（DSH 原生能力）；R2 保留可复制摘要。
- **A**：成立（这是纯执行层缺陷，原文受产品能力限制）。
- **B**：R1 即最小。
- **C**：反方——文件形态对用户不够直观。缓解：生成 `PROGRESS.md` 视图，摘要导出仍保留。
- **D**：需遵守工作区沙箱边界（见 W10）。
- **E**：文件存在 + 校验通过 + 新会话可读。
- **F 复审**：维持。
- **裁定**：**采纳 R1；R2 降为导出选项保留。**

### W06 重认知轻动机

- **位置**：§九（264–293）全部为认知分支；§十二 350"鼓励应基于具体进展"。
- **候选**：R1 增加动机/情绪干预流程；R2 增加进度计数与打卡；R3 仅在受阻分类中增加"时间/动力不足"分支。
- **A**：部分成立。原文确无动力分支，但"不想学"多由任务跨度过大（§九已有"任务跨度过大"）或时间不足引起，属结构问题。
- **B**：R3 最小。
- **C**：强反方——教练没有可靠手段处理情绪问题；以"鼓励"回应情绪困扰可能造成伤害；引入不可验证的"情绪评估"与全文证据驱动原则冲突。
- **D**：R1/R2 引入不可验证信号，回归风险高。
- **E**：R3 可观察（受阻分类新增分支，措施均为原文已有手段）。
- **F 复审**：**翻案记录。** 第一轮倾向 R1（作者上一轮曾建议增加动机管理）。第二轮重读 §九后认为：证据不足、越界、与证据驱动原则冲突，改判 R3。这是本次审核中唯一被推翻的自身结论。
- **裁定**：**驳回 R1、R2；微采纳 R3。**

- **位置**：§八（255–258）。

- **A**：成立。
- **B**：R1 是显式化已有原则，改动极小。
- **C**：反方——R1 可能与"有条件通过"重叠。缓解：三条缺一即"有条件通过"；核心目标未达成才"未通过"。
- **D**：与 §八三档结论一致。
- **E**：校验器强制结论枚举与 `retrievalRecap` 规则。
- **F 复审**：维持。R2 无实证依据，且量表会诱发新的虚假精确（同 W03）。

### W10 权限粒度与授权延续未定义

- **位置**：§十一（327–339）。
- **失败场景**：审阅代码、读日志、跑测试是高频动作；原文只规定"操作前说明"，未定义授权有效期，实践中要么反复打扰用户，要么一次授权被无限扩大。
- **候选**：R1 授权记录表（对象 + 操作类型 + 时间）：同一对象的**只读**操作一次授权后可延续，写操作每次重新确认；R2 保持原样。
- **A**：成立。
- **B**：R1 最小且不放松任何安全边界。
- **C**：反方——授权记录可能被误读为"永久许可"。缓解：记录仅用于**减少重复询问**，写操作一律重新确认，最终强制层是 DSH 沙箱，不是教练规则。
- **D**：安全上必须保守：不因记录而扩大范围。
- **E**：授权写入状态文件，复盘时可审阅。
- **F 复审**：维持，并加固约束。
- **裁定**：**修改后采纳 R1（附安全约束条款）。**

## 5. 残余风险与已知边界（如实声明）

1. **校验器只覆盖状态层与领域包结构。** 它能强制"无证据不得标已验证""阻塞项未清不得通过"，但不能验证对话中是否真的只给了 3 级提示、是否给了完整答案。提示级别体现在任务卡的提示记录表与对话中，状态层不强制记录（第 3 轮据复核结论修正了原先提到的 `hintLevel` 字段——该字段并不存在）。
2. **引擎仍依赖模型遵守 SKILL.md。** 机械校验降低了漂移的后果，但未消除漂移。
3. **领域包内容需实测。** Unity 命令行参数依赖官方文档核对，标注"（未验证）"的条目在真实环境中必须实测后才可用于验收。
4. **技能加载验证条件。** 工作区 `.dsh/skills` 属 DSH 的 `project-dsh` 根，按官方说明可免重启被发现；但若本机会话未刷新目录，需要重启宿主或新会话。
5. **原文未覆盖的领域**：多人协作教学、学员之间的比较、证书/学分之类的外部认定，均不在本设计范围。
